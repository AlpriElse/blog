## Project Structure

Each project in the sandbox should follow this structure:

```
sandbox/
├── your-project-name/
│   ├── package.json          # Required: must include a "build" script
│   ├── dist/                 # Generated by build (gitignored)
│   ├── node_modules/         # Dependencies (gitignored)
│   └── ...                   # Your project files
```

## Adding a New Project

1. **Create a new directory** in `sandbox/`:
   ```bash
   mkdir sandbox/your-project-name
   cd sandbox/your-project-name
   ```

2. **Initialize your project** with a `package.json`:
   ```bash
   npm init -y
   ```

3. **Add a build script** that outputs to `dist/`:
   ```json
   {
     "scripts": {
       "build": "vite build",
       "dev": "vite"
     }
   }
   ```

4. **Build and test locally**:
   ```bash
   npm install
   npm run build
   ```

5. **Build all sandbox projects**:
   ```bash
   cd ../..
   npx tsx scripts/build-sandbox.ts
   ```

Your project will be available at `/sandbox/your-project-name/` when the main site is deployed.

## Build Configuration

The build script (`scripts/build-sandbox.ts`) automatically:
- Discovers all projects with a `package.json` in the `sandbox/` directory
- Installs dependencies if `node_modules/` doesn't exist
- Runs `npm run build` for each project
- Copies the `dist/` folder to `public/sandbox/<project-name>/`

### Skipping CI Builds (Pre-built Projects)

Some projects have heavy dependencies (large WASM files, ML models, etc.) that are too resource-intensive to build in Cloudflare's build environment. These projects should be:

1. **Built locally** on a machine with sufficient resources
2. **Committed to git** (the built output in `public/sandbox/<project-name>/`)
3. **Skipped in CI** by adding to the `PREBUILT_PROJECTS` array

To configure a project as pre-built:

1. **Edit** `scripts/build-sandbox.ts`:
   ```typescript
   const PREBUILT_PROJECTS = ["poc-subtext", "your-project-name"];
   ```

2. **Update** `.gitignore` to allow committing the build output:
   ```gitignore
   # In .gitignore:
   public/sandbox/*
   !public/sandbox/your-project-name/
   ```

3. **Build locally and commit**:
   ```bash
   npm run build
   git add public/sandbox/your-project-name/
   git commit -m "Add pre-built output for your-project-name"
   ```

The build script will skip this project during CI builds and use the committed files instead.

## Managing Large Assets

Cloudflare Pages has a **25MB limit per file**. For larger files, you have two options:

### Using R2 for Large Files

R2 (Cloudflare's object storage) is the recommended approach for large media files (videos, zip archives, etc.).

#### Automatic Upload for Large Files

Files matching these patterns and exceeding **20MB** are automatically uploaded to R2:
- `**/*.mp4`
- `**/*.mov`
- `**/*.webm`
- `**/*.zip`

#### Manual Upload with `.r2` Marker

To upload **all files** in a directory to R2 (regardless of size or extension):

1. **Create a `.r2` marker file** in the directory:
   ```bash
   touch sandbox/your-project/public/screenshots/.r2
   ```

2. **Upload to R2**:
   ```bash
   npx tsx scripts/upload-r2-assets.ts
   ```

   Preview uploads without actually uploading:
   ```bash
   npx tsx scripts/upload-r2-assets.ts --dry-run
   ```

3. **Add files to `.gitignore`** to exclude them from the repo:
   ```gitignore
   # In .gitignore:
   sandbox/your-project/public/screenshots/*.jpg
   ```

4. **Use R2 URLs in your code**:
   ```javascript
   // Load the manifest
   import manifest from '../../../r2-manifest.json';

   // Get R2 URL for a local path
   const imagePath = 'sandbox/your-project/public/screenshots/image.jpg';
   const imageUrl = manifest[imagePath]?.r2Url || `/local/path/${imagePath}`;
   ```

The script generates `r2-manifest.json` at the project root, mapping local paths to R2 URLs.

#### Example: poc-subtext

The `poc-subtext` project uses `.r2` markers to upload all screenshots:

```
sandbox/poc-subtext/public/examples/simon-kim/screenshots/
├── .r2                    # Marker file
├── clip_000_0.00s.jpg     # Uploaded to R2
├── clip_001_3.26s.jpg     # Uploaded to R2
└── ...                    # All files uploaded
```

### Using Git LFS

Git LFS (Large File Storage) is used for **binary source files** that need to be versioned but are too large for standard git. Currently configured for:

- **WASM files**: `*.wasm`
- **Large JSON data**: terrain-data.json, contour-data.json, track-data.json
- **Built WASM assets**: `public/sandbox/**/assets/*.wasm`

To add a new file type to LFS:

1. **Edit** `.gitattributes`:
   ```
   *.your-extension filter=lfs diff=lfs merge=lfs -text
   ```

2. **Track existing files**:
   ```bash
   git lfs track "*.your-extension"
   git add .gitattributes
   git add your-large-file.extension
   git commit -m "Add large file to LFS"
   ```

**When to use LFS vs R2:**
- **Use R2** for: Large media files that are generated/processed, files that change frequently, files that don't need version history
- **Use LFS** for: Binary source files (WASM, models), files that need version control, files that are dependencies for builds

## Local Development

1. **Navigate to your project**:
   ```bash
   cd sandbox/your-project-name
   ```

2. **Install dependencies**:
   ```bash
   npm install
   ```

3. **Start dev server**:
   ```bash
   npm run dev
   ```

4. **Build and preview locally**:
   ```bash
   npm run build
   npm run preview  # If you have a preview script
   ```

## Deployment

### Automatic Deployment (CI)

When you push to the main branch:

1. GitHub Actions / Cloudflare builds the main site
2. The build script (`scripts/build-sandbox.ts`) runs automatically
3. Projects are built and copied to `public/sandbox/<project-name>/`
4. Pre-built projects are skipped (uses committed files)
5. The site is deployed to Cloudflare Pages

### Manual Build

To build all sandbox projects locally:

```bash
npx tsx scripts/build-sandbox.ts
```

Options:
- `--clean`: Clean the `public/sandbox/` directory before building
- `--verbose` or `-v`: Show detailed build output

To build a single project:

```bash
cd sandbox/your-project-name
npm run build
```

## Common Patterns

### Example package.json

```json
{
  "name": "your-project-name",
  "private": true,
  "version": "0.0.0",
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  },
  "dependencies": {
    "react": "^19.0.0"
  },
  "devDependencies": {
    "@vitejs/plugin-react": "^5.0.0",
    "vite": "^7.0.0"
  }
}
```

### Example vite.config.ts

```typescript
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
  base: '/sandbox/your-project-name/',
  build: {
    outDir: 'dist',
  },
});
```

## Troubleshooting

### Build fails in CI but works locally

- Check memory usage - your project might need to be pre-built (see [Skipping CI Builds](#skipping-ci-builds-pre-built-projects))
- Verify all dependencies are in `package.json`
- Check if you're using local files that aren't committed

### Large files not deploying

- Check file size - if over 25MB, use R2 (see [Using R2](#using-r2-for-large-files))
- Verify files aren't in `.gitignore` (unless using R2)
- Check if files should be in Git LFS (see [Using Git LFS](#using-git-lfs))

### R2 URLs not working

- Run `npx tsx scripts/upload-r2-assets.ts` to upload files
- Check `r2-manifest.json` for the correct URL mapping
- Verify the bucket is configured for public access in Cloudflare dashboard

### Project not appearing on site

- Verify `package.json` exists with a `build` script
- Check that `npm run build` creates a `dist/` folder
- Run `npx tsx scripts/build-sandbox.ts` to test the build
- Check `public/sandbox/<project-name>/` for build output
